# Register IDs and naming

- `engineering/scope_register.json` is the contract: `work_packages` (36 WPs, WP-01..39; release, hours, owner), `retired_work_packages` (WP-18, WP-19, WP-21 — retired, marketing omitted v0.3; never built), `features` F-xxx (`wp`, `screens`, `calcs`, `connectors`, `disposition` IN | CONDITIONAL | NA | OMITTED), `requirements` REQ-001..193 (feature, acceptance, `priority` MUST | OMITTED), `screens` SCR-001..137, `calculations` CALC-001..114 and `connectors` CON-01..33 (CON-30/31 write stubs in `connector_stubs`), each with `scope` IN | OMITTED. `engineering/golden_vectors.json` holds GV-001..155, each naming its CALC (the 16 vectors of OMITTED calcs carry the marker `omitted_v03` and are traceability only). Register version v0.3 rev 2 (Owner decisions and review 2026-10-10): 172 features (23 OMITTED), 193 requirements (169 MUST, 24 OMITTED), 31 connectors (9 OMITTED), DRAFT — NOT APPROVED.
- OMITTED IDs (the marketing function) are never build work: do not create code, routes, tables, tests or connectors for them.
- Use the IDs in test names, commit messages, PR titles and code comments (`# CALC-007`). `python engineering/check_register.py` scans docs/, prompts/ (incl. `prompts/.claude/rules/*.md`) and integration/ and fails on any unknown ID; run it before and after every change together with `python engineering/reference_calcs.py`.
- CONDITIONAL features are built behind flags with fixture-only paths until a human confirms the dependency (Brand Registry, API access, app of record, DISC- items in `integration/connector_contracts.md`).
- Contexts (spec §2) and their schemas: workspace `ws`, ingestion `ing`, ledger `ledger`, costing `cost`, profit `profit`, advertising `ads` (ad spend only), customers `cust`, inventory `inv`, moneyback `mb`, alerts `alert`, automation `auto`, reporting `rep`, explain `xpl`, b2b `b2b`, tax `tax`, platform `platform`. Python package `api/src/app/<context>/{domain,service,repo,api}`; `import-linter` enforces that `domain/` imports no framework code and cross-context access goes through services or read-only projections.
- Tables are schema-qualified singular (`ws."user"`, `ws.permission_scope`, `ing.raw_payload`, `ledger.fee_event`, `cost.cost_batch`, `auto.automation_proposal`, `auto.kill_switch`, `platform.audit_log`). Every business table carries `workspace_id`.
- Branches `wp-XX/<slug>` (one Codex task per WP slice; PR title `WP-XX: <title>`); migrations `api/alembic/versions/NNNN_<slug>.py`, one per PR; runbooks `docs/runbooks/RB-NN_<slug>.md` (RB-01..RB-16); change-control entries `CC-nnn`.
